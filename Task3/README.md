# Задание 3. Оценка Data Encryption at Rest and In Transit

Вам необходимо разработать стратегию защиты данных в рамках всей системы. При этом важно учесть особенности шифрования данных, которые находятся в разных состояниях — при хранении и во время передачи.

# Решение

| Данные | В чём необходимость защиты | Инструменты защиты |
| --- | --- | --- |
| **Персональные данные клиентов** (ФИО, дата рождения, телефон, e-mail, адрес, журналы записи) | - Персональные данные;<br/> - риски утечки клиентской базы, спама, социальной инженерии и мошенничества | **При хранении:** <br/> - шифрование БД, директорий с данными, бэкапов<br/> - маскирование и обезличивание в аналитических витринах, строгие ACL на общих папках. <br/><br/> **При передаче:**<br/> - TLS-шифрование между системами<br/>- TLS для Exchange <br/><br/> **Контроль:**<br/>- DLP на e-mail и веб-каналах<br/>- сканирование хранилищ на PII<br/>- SIEM-корреляция массовых выгрузок контактов. |
| **Документы и сканы** (паспорт, полис, согласия на обработку ПДн, договоры) | - Персональные данные;<br/> - риски утечки клиентской базы, спама, социальной инженерии и мошенничества | **At rest:** шифрование каталогов с документами, FDE серверов, ограничения на копирование/печать, доступ к папкам с документами только по ролям (регистратура/юристы/HR). **In transit:** TLS для почты и веб, шифрование вложений (шифрованные архивы, S/MIME/GPG при необходимости). **Контроль:** DLP по шаблонам паспортов/полисов, сканирование общих папок на наличие сканов документов, SIEM-алерты при массовой выгрузке сканов. |
| **Медицинские данные клиентов** (диагнозы, назначения, результаты анализов, файлы и журналы) | - Специальная категория ПДн и медицинская тайна;<br/> - регуляторные и репутационные риски<br/> - риски шантажа и дискриминации пациентов | **При хранении:**<br/>- полное шифрование дисков серверов (SED, AES-256)<br/>- шифрование БД и критичных полей (диагноз, результаты)<br/>- шифрование резервных копий<br/>- RBAC по ролям (врач/ресепшн/ИТ/мед.лабаратория)<br/><br/> **При передаче:**<br/>- TLS 1.2+/1.3 для портала/ЛК и внутренних API<br/>- mTLS для интеграций (лаборатория, внешние сервисы)<br/>- VPN между филиалами<br/><br/> **Контроль:**<br/>- централизованный сбор логов доступа к мед.данным<br/>- DLP по мед.шаблонам |
| **Финансовые данные клиентов и компании** (переводы, чеки, счета, реквизиты контрагентов, зарплаты) | - коммерческая тайна и финансовые данные<br/>- риски подмены реквизитов, финансового мошенничества, налоговых претензий и утраты доверия партнёров | **При хранении:**<br/>- шифрование дисков серверов 1С и файловых хранилищ<br/>- шифрование архивов с отчётами<br/>- RBAC по ролям (бухгалтер, руководство)<br/><br/> **При передаче:**<br/>- защищённые протоколы с банком, ОФД и гос.органами (TLS/VPN)<br/>- TLS для интеграций между 1С и другими системами<br/><br/> **Контроль:**<br/>- журналирование операций с платёжными данными<br/>- контроль целостности отчётных файлов (подписи/хэши)<br/>- мониторинг аномальных платежей |
| **Данные о ТМЦ** (остатки, движение, цены, договорова, поставщики) | - коммерческая тайна<br/>- риски конкурентной разведки, подмены складского учёта | **При хранении:**<br/>- шифрование БД 1С и бэкапов<br/>- RBAC по ролям (склад/ИТ/мед.лабаратория)<br/>- контроль целостности данных.<br/><br/> **При передаче:**<br/>- TLS/VPN при обмене с внешними системами (поставщики, учётные системы).<br/><br/> **Контроль:**<br/>- аудит изменений по справочникам ТМЦ и цен<br/>- DLP-правила для прайс-листов и отчётов. |
| **Аналитические данные** (DataLake, витрины BI/ML/AI) | - риск массовой утечки и искажения аналитики | - Шифрование хранилищ<br/>- разделение прав на сырые и агрегированные слои<br/>- обязательное маскирование и обезличивание<br/>- RBAC по ролям (аналитики, руководство)<br/>- Автоматизированные проверки маскирования и обезличивания |
| **Учётные данные и секреты** (хеши паролей, токены, ключи API, приватные ключи, сертификаты, мастер-ключи шифрования, секреты интеграций) | - риск компрометации учетных записей<br/>- риск взлома и утечки всех систем | - Хранение паролей только в виде стойких хешей<br/>- использование хранилища секретов (vault/KMS) для ключей и конфигураций<br/>- аппаратные/сетевые HSM для мастер-ключей<br/>- жёсткое разграничение доступа по принципу наименьших привилегий<br/>- регулярная ротация ключей<br/>- аудит использования секретов |
| **Персональные данные сотрудников** (анкеты, договоры, приказы, история зарплаты, контакты) | - риск правовых последствий и внутренних конфликтов при утечке зарплат и персональных данных | - шифрование папок HR на файловом сервере<br/>- RBAC по ролям (HR, руководство)<br/>- шифрование БД кадрового учета<br/>- TLS/VPN для удалённого доступа к HR-системам<br/>- аудит доступа к HR-папкам и таблицам<br/>- DLP-правила по кадровым документам |
| **Аудит, логи, мониторинг** (логи приложений, аудит доступов, события безопасности) | - могут содержать идентификаторы пользователей/пациентов<br/>- риски подмены/удаления данных | - Централизованный сбор логов в защищённое хранилище (SIEM/лог-платформа)<br/>- шифрование каналов доставки логов (TLS)<br/>- шифрование дисков хранилища логов<br/>- политика «только добавление» и длительное хранение<br/>- RBAC по ролям (ИТ, ИБ)<br/>- контроль целостности логов (подписи, хэши)<br/>- алерты при попытках отключения или изменения логирования. |
